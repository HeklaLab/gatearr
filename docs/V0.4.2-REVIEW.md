# Gatearr 0.4.2 — development review

Implemented locally on `codex/v0.4.2`; no release, image or GitHub publication has been performed for this version.

## Interface

- The approved **Paysage diffus** artwork is shared by the portal, administration and builder previews. Local SVG artwork is generated from validated theme colors, without an external image dependency. Explicit authored page backgrounds remain under the page author’s control. The theme editor updates the artwork alongside draft colors.
- Glass follow-up: darker, less frosted surfaces retain fine specular edges and cast shadows. Header and local capsules have a clearer selected state. Sidebar entries and child entries use the same fully rounded selection, with a 520 ms eased sliding highlight. The sidebar remains connected while only the administration content is replaced, avoiding animation resets during loading. Sidebar observers disconnect when their menus leave the page. Reduced motion disables the slide.
- Live navigation checks cover an in-progress sidebar slide, progressively expanding/collapsing child menus, preserved header/sidebar nodes, browser back, Home → Administration and mobile width. Submenu layout and the selection marker share one motion clock instead of restarting competing transitions.
- Publishing a theme reloads its stylesheet and preloads its landscape before the atomic swap. Navigation waits for a pending theme update before clearing draft colors. All six actual apply/publish → Home → Administration journeys were exercised on an isolated demo copy.
- Integration cards keep the overview in place and move the chosen configuration directly below it, without native fragment jumps. Delegated selection still works after a connection response replaces the cards.
- Portal application cards have a logo/title header, optional real media counts or request quotas immediately below, and a visible opening affordance; account access is shorter. Large cropped background logos fill the card, with the original 512 px Emby artwork and upstream vector Seerr artwork. Custom application images remain respected.
- Approved **Paysage diffus** glass uses each theme's own background, surface, text and accent. Light themes use denser glass; reduced transparency and unsupported blur fall back to opaque surfaces.
- Common box radii and capsule buttons retain the existing header/navigation geometry. The account language list has a sliding highlight and respects reduced motion.
- Native checkboxes keep their form names, validation, disabled state, label and change events. Their presentation becomes an animated ON/OFF switch, including controls created by the builders. Saving and destructive confirmations retain their existing behavior.
- Mouse navigation focuses the destination heading without a persistent outline. Keyboard navigation retains a visible destination focus indicator.
- Mobile user tables reflow into labeled rows instead of expanding the page width.

## Language management

Translations now offers **Managed by the user** or **Managed by the group**. Group settings provide a language or the default Gatearr language. An empty, inactive or missing group language resolves to the active Gatearr default, including users without a group. Switching policy does not overwrite a user's saved personal choice.

Personal language selectors are replaced by a managed-language notice in group mode; direct personal-language submissions are rejected server-side. Interface, transactional email and Seerr synchronization use the same effective language. Group updates use the existing group version lease. Migration `0022` adds a nullable language column and leaves existing groups unchanged.

New strings have French and English wording. Other bundled catalogs retain explicit English fallback wording for these additions; this review does not claim native proofreading of those language packs.

## Application-card information

Standalone Emby/Jellyfin and Seerr widgets are removed from the builder palette. Their information appears inside the matching application card, enabled in fresh layouts and builder presets, with a per-application ON/OFF control and selectable metrics. Existing widget settings, group/role audiences and priorities migrate in memory into the card configuration; empty containers created solely for those widgets disappear. The next save persists the normalized layout. Settings for a temporarily absent application remain stored. Disabling card information survives reloading and publishing. Tracearr and library announcements remain standalone.

Media cards retain exact mode and add a per-card promotional mode, rounded down to tens or hundreds. The `+` suffix is only shown when the actual count strictly exceeds the displayed floor. Small values and exact thresholds are not exaggerated. Episodes use the same native user-scoped query as movies and series.

Seerr shows the remaining count, request type, actual period when available, limit and a remaining-quota bar. A seven-day window is described as seven days, without inventing a calendar-week reset. Unlimited privileges, exhausted quotas, malformed/inaccessible data and unknown periods have separate states. Progress bars align even when labels wrap. No redundant application-launch buttons were added.

## Tdarr

The proxy now scopes URLs created by fetch, XHR, dynamic resources, EventSource and WebSocket at runtime, as well as root-relative CSS resources. Native authentication stays active. Gatearr cookies remain excluded from upstream requests. An incomplete UI load displays a retry action instead of remaining silently blank.

The [official Tdarr distribution](https://storage.tdarr.io/versions.json) was used for a separate local **Tdarr 3.01.00** server, bound to loopback with authentication enabled, no libraries and no nodes. Through the Gatearr proxy, the review verified:

- the native first-account screen;
- creation and login of an isolated test account;
- the native dashboard and API calls;
- three WebSocket connections exchanging frames through the protected proxy;
- no browser script errors in that journey.

No media, transcoding job or existing Tdarr installation was used. The original reported installation still needs its own confirmation; this does not establish the cause of its earlier white screen. The temporary test connection is removed after review. The [official subpath guidance](https://docs.tdarr.io/docs/installation/extra/) is the reference for upstream path behavior.

## Approved administration directory and SMTP history

The administration landing page now implements **Répertoire avec cartes**, not the open-background alternative: two columns with explicit destinations and three compact communication/monitoring cards. The existing sidebar stays in place. Directory, email-log and pagination links participate in the existing dynamic navigation.

**Activity log → Email log** and the simple links in Emails/the template editor share `/admin/activity/mail`. Migration `0023` adds `mail_deliveries`, independent of transient `mail_jobs` and user records. The log starts at activation; pre-existing SMTP messages cannot be reconstructed. It stores recipient, sanitized subject, purpose/context, UTC time, acceptance/failure state and a fixed safe error classification. It does not retain bodies, recovery links, credentials or raw SMTP error responses. SMTP acceptance is deliberately distinct from inbox delivery.

All message-producing SMTP calls share the logger, including notifications, account emails, SMTP tests and unsaved template tests. A connection-only probe is not recorded as a message. Metadata is buffered on the calling session and written after its outer transaction ends, including rollback/close, so draft-test savepoint rollback neither erases the log nor saves the draft. A QUIT failure after SMTP acceptance is logged as accepted and does not request a duplicate resend. Every retry remains a distinct attempt. Administrator checks apply to both the page and pagination; rows are escaped and paged with a stable ID cursor.

Validation covers all configured SMTP transports, accepted/refused/failed attempts, outer commit/rollback/close, unsaved template tests, queue delivery, sensitive-subject redaction, permission boundaries, escaped content and schema migration preserving existing settings. Browser review uses an isolated database and a loopback-only SMTP capture service, verifies actual SMTP acceptance for an SMTP test and an unsaved template test, stationary navigation, shared links, mobile layout and reduced motion. The six-theme visual export includes the directory and populated success/failure mail history, extending the matrix to 156 views.

Final directory/mail-log validation: **446 tests passed, 1 optional export skipped**, one dependency warning. The separate theme export passes eight checks. The updated **156-view** browser matrix has no checked contrast, overflow, raw-checkbox or script finding. ## Bazarr subtitle-language permission and shorter navigation

Sidebar selection uses 220 ms and submenu expansion/collapse 200 ms, retaining the natural-content measurement and reduced-motion path. No artificial wait is added to page navigation.

Applications & API → Bazarr offers an opt-in shared subtitle-profile setting. The administrator loads the authenticated native profile list, chooses one existing profile, and saves this independently of the connection credentials. The setting records a connection fingerprint: switching the upstream or API key requires reselecting the profile. `0024` adds `users.bazarr_subtitles`, default false for all existing users. This permission is independent of Bazarr interface/tool access and administrator status. Group-managed values use the existing reviewed membership flow and restore the individual baseline when removed. The individual control uses the existing protected admin-tools form.

Authorized users see a compact Subtitle languages card in My account. It shows the shared profile/current languages and offers additions from Bazarr's native language catalog; inactive selected languages are enabled while retaining all enabled languages. A repeated addition is idempotent. Forced/HI/audio rules, cutoff, tags, other options and every other profile are retained. The user cannot supply an upstream, API key or arbitrary profile. Permission/configuration are checked again immediately before writing. SMTP, Seerr and tool grants are unaffected.

Native contract references: [profile list](https://github.com/morpheus65535/bazarr/blob/master/bazarr/api/system/languages_profiles.py), [language catalog](https://github.com/morpheus65535/bazarr/blob/master/bazarr/api/system/languages.py), [settings writer](https://github.com/morpheus65535/bazarr/blob/master/bazarr/api/system/settings.py), and [native profile editor](https://github.com/morpheus65535/bazarr/blob/master/frontend/src/components/forms/ProfileEditForm.tsx).

Bazarr's internal settings writer accepts the complete profile list, rather than a single-language patch. Gatearr serializes its own writes, rereads before writing to reject detected edits and validates the readback. **The native endpoint has no conditional-write token**: an edit made directly in Bazarr during the final read/write window cannot be made atomic by Gatearr. No claim of external concurrency safety or real subtitle download is made. Searches, cutoff behavior and downloads remain governed by Bazarr. Unsupported response schemas and failures return safe messages instead of displaying remote bodies or secrets.

Validation: **458 tests passed, 1 optional export skipped**, one dependency warning; **8 theme export checks** and **180 browser views** with no checked contrast/overflow/script/switch-layout finding. Additional targeted checks cover successful/duplicate additions, preserving another profile and all enabled languages, invalid/stale targets, revoked permissions, group inheritance/restoration and reviewed group saves, remote failures/readback failure and preservation across migration. A loopback-only API contract fixture exercises profile loading, a real form submission/native-style settings response, readback and mobile layout in an isolated copy. **This is not validation against the user's real Bazarr server.** No Bazarr connection or permission was automatically enabled in the main demo. ## Personal subtitle choices, capacity and persistent fictitious Bazarr demo

The card displays selected/allowed capacity (for example **1/3**), + adds a selection row, − removes a row, and + is disabled at capacity. Removing a personal choice frees a slot; it never deletes a shared Bazarr language. All native languages remain offered regardless of the common profile or other users. Choosing an already configured language consumes one personal slot and produces the same neutral saved response as any other selection, without warning or redundant native settings POST. The user's card does not expose the shared profile, other people's choices or integration configuration text. It explicitly explains that availability varies by library title.

Backend checks enforce capacity and current permissions independently of the button state. Concurrent stale personal forms are rejected. ## Subtitle replacement policies and dynamic preference saves

Applications & API → Bazarr now offers three replacement policies: **free changes**, **lock for 1–3650 days**, and **locked until administrative intervention**. Existing installations retain free changes until an administrator chooses another mode. Locked selections cannot be edited or removed; additions can use remaining capacity. Choices already present in the native shared profile receive the same personal lock as new native additions. Migration `0026` initializes timestamps for existing choices without changing their values or quota. Policy changes apply to existing selections too; changing the timed policy starts its duration from the policy change. A per-language administrative release lasts until that selection is replaced, and its replacement starts a new lock. The user profile's Groups/admin-tools tab includes individual unlock buttons, independent of group-managed access. Unlocking never edits native profiles or changes permissions.

Locked fields retain hidden form values and are enforced again server-side against the current policy, so disabled UI controls are not the security boundary. Temporary locks expire at their UTC deadline; permanent locks require an administrative release or a policy change. A stale user form following an administrative release is rejected by the separate preference version. Removing an unlocked selection still retains all native shared languages.

The user card requires the individual effective permission, enabled service with URL/key, an enabled shared profile setting bound to the current connection, and successful native profile/catalog reads. Incomplete, removed, rejected or unavailable native configuration hides the card rather than showing administrator setup instructions to a member.

User saves, Bazarr policy saves and administrative releases use `save-feedback.js`, local save regions and delegated controls. Spinner/success feedback runs without reloading the document; updated hidden versions, locks and capacity replace the local region. Repeated edits remain functional after replacement and controls are frozen during the user save. Other successful preference forms without local regions use the capsule navigation refresh, retaining same-page scroll and updating translated content/header without a document reload. Authentication redirects retain their existing native behavior.
