Development authorized by the user on 30 October 2026. The approved changes below are implemented and verified. Version 0.5.1 and GitHub publication were authorized on 2 November 2026; the installed changelog now includes this release. See `0.5.1-qa.md` for validation.

## #20 — Allow notification emails without `${link}`

- Issue: https://github.com/HeklaLab/gatearr/issues/20
- Added on 30 October 2026 after reproduction against 0.5.0 on an isolated test database; no messages were sent.
- Confirmed: all six templates save with `${link}`, fail with HTTP 400 after its removal, and save again when it is restored. The previously saved template remains intact after rejection.
- Cause: shared email validation requires `${link}` in every message body without considering its purpose. The legacy plain-text template endpoint applies the same blanket requirement.
- Planned behavior: make the link optional for email-change, password-change and new-season notifications. Keep it mandatory for invitations, email-address verification and password recovery.
- Apply the same purpose-aware rule to visual-editor saving, previews, test sends, translations and the legacy plain-text editor. Adapt the editor hint so it only calls the link required where necessary. Retain HTML sanitization and variable validation.
- Validation before release: test each template with and without a link, restore/reopen saved content, preserve existing content after rejected mandatory-link edits, and verify rendered notification messages can omit the link. Test translated templates and all relevant editor actions.
- Reproduction evidence in the parent workspace: `work/issue20-reproduction-20261030.json`.
- Status: implemented and verified locally; not released.

## #16 — Reapply the current text colour

- Issue: https://github.com/HeklaLab/gatearr/issues/16
- Reproduced on 30 October 2026 in 12 isolated editor contexts: Emby/Seerr guide steps, text blocks on Home/custom/access-guide/system/header/footer pages, and accordion answers.
- Confirmed case: colour one selection, select different text, then reopen and accept the same colour. The second selection is unchanged. Choosing a different colour works, and saved formatting survives reopening. The email block-colour controls did not reproduce this failure.
- Cause: the shared rich-text component applies colour only on the colour input's value-change event. Accepting its current value does not reapply it to a new selection.
- Planned correction: provide distinct actions to apply the current colour and choose a colour, preserve the selected text, and ensure repeated use works without changing colour or reopening the editor. Do not apply a colour merely because a picker was opened or cancelled.
- Verify all shared-editor contexts, including repeated same/different colours, separate selections, saving/reopening and safe rich-text sanitization.
- Evidence in the parent workspace: `work/issue16-reproduction-20261030.json`.
- Status: implemented and verified locally; not released.

## #18 — Optional application status and compact warning banner

- Issue: https://github.com/HeklaLab/gatearr/issues/18
- Approved graphical direction: the compact banner variant of the application-status proposal.
- Add two independent options to the Applications block: show a warning when an application has connection problems, and show a green/red status indicator on the affected application card.
- The compact warning banner appears only on the affected card when the warning option is enabled. Proposed user-facing message: “Ce service rencontre des difficultés. L’accès peut être perturbé.” Make the message available in Labels & Translations.
- Preserve an unknown/not-yet-checked state rather than claiming the service is healthy or offline without evidence. Do not expose private connection diagnostics to end users.
- Current connection checks are demand-driven with a 60-second result cache, not continuous background monitoring.
- Approved addition: check configured and enabled integrations automatically every 60 seconds, even when nobody is visiting the portal. Reuse the results for application-card status; do not launch a separate probe per visitor. Avoid overlapping checks, handle timeouts, and preserve an unknown/stale state when results are unavailable. Implemented as an independent background task; cached public reads do not probe upstream servers.
- Status: implemented and verified locally, including independent options and all three health states; not released.

## #21 — Reduce whitespace around short text blocks

- Issue: https://github.com/HeklaLab/gatearr/issues/21
- Reviewed on 30 October 2026; no issue comments at review time. The title asks for horizontal sizing, but the description specifically reports excessive whitespace above and below a one-line Home message.

## #22 — Font size in rich-text editors

- Issue: https://github.com/HeklaLab/gatearr/issues/22
- Reviewed on 30 October 2026; no issue comments at review time. Request: font-size choices across blocks that provide rich-text editing.
- Source inspection confirms the shared formatting toolbar currently offers emphasis, lists, alignment and colour, but no font-size control.
- Approved presentation: add a compact font-size selector immediately after bold, italic and underline in the shared toolbar for text blocks, accordion answers and guide instructions. Apply changes only to selected text. Audit other editors, including emails, for equivalent appropriate controls.
- Choices: “Par défaut”, 12, 14, 16, 18, 20, 24 and 32 px. “Par défaut” restores the normal inherited text size. Show “Tailles variées” when the selection contains multiple sizes; this is an informational state, not an applicable size.
- Preserve the selection when operating the selector and keep the same presentation and behaviour across shared editors. Disable the selector when no text is selected.
- Approved interactive proposal: `gatearr-rich-text-size.html` in the thread visualization directory. User approved the proposal and subsequently authorized its implementation.
- Any implementation must preserve sizes through sanitization, saving, reopening and publication, retain an option to restore the default size, and use natural translated UI labels.
- Status: implemented in the shared toolbar, including the email editor, and verified locally; not released.
