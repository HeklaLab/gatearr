# Gatearr 0.5.1 — release validation

Local validation began on 30 October 2026. Release preparation and GitHub publication were authorized on 2 November 2026. Version 0.5.1 includes the validated changes below. Publication status is tracked by the GitHub release and CI run.

## Scope

- Purpose-aware email links (#20), reusable text colours (#16), one shared colour control, header editing restricted to its builder, removal of Navigation position, per-block guide display scope (#19), optional application health/banner and automatic checks (#18), complete guide breadcrumbs (#17), compact text spacing (#21), and shared text-size controls (#22).
- Tracearr member application access (#15) and music albums (#7) are excluded.
- Existing guide blocks default to their previous entire-journey behaviour unless the administrator changes their scope. Existing layouts, identities and permissions are retained. New application health options are opt-in.

## Automated verification

- Full Python suite: **683 passed, 1 skipped** (optional browser-review export). The existing dependency deprecation warning remains.
- `tests/test_release051.py`: 14 targeted cases cover all six email purposes, save/preview/test and legacy validation, Emby/Seerr guide scopes, public and draft previews, breadcrumbs through reused guide branches, permission-filtered cached health, stale/disabled states, independent monitoring, all seven integration probes, safe formatting and bundled public translations.
- The legacy navigation test now verifies that the removed navigation-position parameter does not change the saved navigation. Sidebar placement and theme edits remain covered.
- JavaScript syntax checks and `git diff --check` pass.

## Browser and SMTP verification

- `tests/browser/check_rich_formatting.cjs`: real Chromium test of size selection, mixed sizes, default size, retained emphasis, applying the same colour to multiple selections, hexadecimal colour entry and disabled size selection at a collapsed caret. Both standard and basic/accordion toolbars pass.
- Isolated HTTP/browser fixture: guide instructions and email content use the same toolbar. Header blocks have no edit outlines in other builders; Navigation position is absent.
- A one-line text card changes from about **110 px** (30 px padding and 24 px bottom margin) to **60 px** with compact defaults. Independent 6 px vertical / 12 px horizontal settings render correctly.
- Warning banner verified in offline, online and unknown states, including disappearance when appropriate. No private connection details are rendered in public cards or the status endpoint. Custom application names do not inherit native application status.
- Theme controls checked at 1440, 900, 768 and 390 px after layout/animation settles: no horizontal page overflow. No browser script errors observed.
- Three notification templates without an action link were saved and sent through the actual mailer to an isolated local SMTP receiver; HTML and plain text were checked. Invitation, verification and recovery templates without their action link were rejected. No external email was sent.
- Live demo monitoring was observed without visiting configuration pages: connection timestamps advanced by **60 seconds**. Disabled integrations are skipped.

## Demo and evidence

- The demonstration at `http://localhost:8855` was backed up and restarted without resetting it. Counts of users, permission groups, content pages, guides and custom menu entries remained unchanged.
- Detailed local evidence is kept outside the repository in the parent workspace: `work/release051-lab-20261030/` (browser screenshots, SMTP captures and results), `work/release051-monitor-results.json` (observed cadence and retained counts), and `work/backups-051/` (private demo backup).
- These checks cover local mocks and simulated failures, not every deployment, reverse proxy or upstream version.
